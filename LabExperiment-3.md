# Experiment 3: Stakeholder Identification and Requirement Elicitation

**Course:** Software Engineering and Design Principles  
**Experiment:** 3 – Stakeholder Identification and Requirement Elicitation  
**Project Title:** Student Placement Management System  
**Domain:** Education and Campus Recruitment

---

## Aim

To identify stakeholders and perform requirement elicitation for the Student Placement Management System using suitable elicitation techniques, prepare user stories, and develop a Requirement Gathering Report.

---

## Objectives

- Identify key stakeholders of the Student Placement Management System.
- Apply suitable requirement elicitation techniques.
- Gather functional and non-functional requirements.
- Prepare user stories with acceptance criteria.
- Document the Requirement Gathering Report.

---

## Introduction

Requirement elicitation is the process of discovering and understanding the needs, expectations, and constraints of stakeholders. It is an important activity in software engineering because clearly defined requirements help in developing software that satisfies actual user needs.

The Student Placement Management System involves multiple stakeholders such as students, placement officers, recruiters, and system administrators. Requirement elicitation helps identify their specific needs related to student profiles, placement drives, eligibility, applications, interviews, shortlisting, and placement tracking.

---

## Selected Project

**Project Title:** Student Placement Management System  
**Domain:** Education and Campus Recruitment

---

# Stakeholder Identification

| Stakeholder | Role | Requirements |
|---|---|---|
| Student | Applies for placement opportunities | Easy profile management, eligibility checking, application tracking |
| Placement Officer | Manages placement activities | Manage drives, students, eligibility, applications and reports |
| Recruiter | Conducts recruitment | Create job requirements, view eligible candidates and shortlist students |
| System Administrator | Manages the system | User management, security, monitoring and system maintenance |
| Faculty Coordinator | Supports placement activities | Monitor student participation and placement progress |

---

# Requirement Elicitation Techniques

| Technique | Purpose | Outcome |
|---|---|---|
| Interview | Discuss placement requirements with stakeholders | Detailed functional requirements |
| Questionnaire | Collect feedback from students and placement staff | User expectations and preferences |
| Observation | Observe existing placement management workflow | Workflow and usability requirements |
| User Personas | Represent different types of users | User-centred requirements |

---

# Sample Requirement Gathering Findings

### Interview Findings

- Students require a simple way to maintain their academic and skill information.
- Placement officers require centralized management of placement drives.
- Recruiters require access to eligible candidates based on job requirements.
- Students need to track their application and interview status.
- Placement officers require placement reports and statistics.

### Observation Findings

- Placement activities are often managed using spreadsheets, forms, emails, and multiple communication channels.
- Students need quick access to eligible placement opportunities.
- Placement officers need a centralized view of applications and selection status.
- Frequently used functions should be easily accessible.

### Questionnaire Findings

- Students expect easy access to placement opportunities.
- Users expect secure authentication and protection of personal information.
- Students want notifications for application and interview updates.
- Placement officers expect accurate and centralized placement data.

# Functional Requirements

1. The system shall allow users to register and log in securely.
2. The system shall provide role-based access for students, placement officers, recruiters, and administrators.
3. Students shall be able to create and update their profiles.
4. Students shall be able to upload their resumes.
5. Placement officers shall be able to create and manage placement drives.
6. Recruiters shall be able to create job requirements.
7. The system shall verify student eligibility based on defined criteria.
8. Eligible students shall be able to apply for placement opportunities.
9. Recruiters shall be able to view and shortlist candidates.
10. The system shall allow interview schedules to be managed.
11. Students shall be able to track application status.
12. The system shall maintain placement and offer records.
13. The system shall generate placement-related reports and statistics.
14. The system shall send notifications for important placement activities.

---

# Non-Functional Requirements

### Performance

- The system should provide responses within an acceptable time under normal load.
- Frequently accessed information should be retrieved efficiently.

### Security

- User authentication and authorization should be implemented.
- Passwords should be securely stored.
- Users should only access resources permitted by their roles.

### Reliability

- The system should maintain consistent placement and application data.
- Transaction failures should not result in inconsistent records.

### Usability

- The interface should be simple and easy to understand.
- Users should be able to perform common operations with minimal training.

### Scalability

- The system should support an increasing number of students, companies, and applications.
- The architecture should allow future feature expansion.

### Maintainability

- The software should follow modular and layered architecture.
- Components should be easy to test, modify, and maintain.

# User Stories

| ID | User Story | Acceptance Criteria |
|---|---|---|
| US1 | As a student, I want to create and update my profile so that my placement information remains up to date. | Student can add, update and save profile information successfully. |
| US2 | As a student, I want to upload my resume so that recruiters can view my qualifications. | Resume is uploaded successfully and associated with the student's profile. |
| US3 | As a placement officer, I want to create placement drives so that students can apply for available opportunities. | Placement officer can create, update and publish a placement drive. |
| US4 | As a student, I want to view eligible placement opportunities so that I can apply for suitable jobs. | System displays placement drives for which the student satisfies eligibility criteria. |
| US5 | As a student, I want to apply for a placement drive so that I can participate in the recruitment process. | Eligible student can submit an application successfully. |
| US6 | As a recruiter, I want to view eligible candidates so that I can shortlist suitable students. | Recruiter can filter and view eligible candidates. |
| US7 | As a recruiter, I want to shortlist candidates so that selected students can proceed to the next recruitment stage. | Recruiter can change the candidate status to shortlisted. |
| US8 | As a placement officer, I want to schedule interviews so that candidates can attend recruitment rounds on time. | Interview date, time and candidate information can be created and updated. |
| US9 | As a student, I want to track my application status so that I know the progress of my application. | Student can view statuses such as Applied, Shortlisted, Interview and Selected. |
| US10 | As a placement officer, I want to view placement statistics so that I can monitor placement performance. | System displays accurate placement statistics and reports. |

# Requirement Gathering Report

The requirement elicitation process identified the major requirements of the Student Placement Management System.

The primary stakeholders identified were students, placement officers, recruiters, system administrators, and faculty coordinators.

The elicitation techniques used were interviews, questionnaires, observation, and user personas. The gathered requirements focused on student profile management, placement drive management, eligibility verification, job applications, candidate shortlisting, interview scheduling, placement tracking, notifications, and reporting.

The stakeholders also emphasized the importance of security, ease of use, reliability, performance, and centralized data management.

---

# Analysis

The gathered requirements indicate that the Student Placement Management System should provide a centralized platform for managing campus placement activities.

The system should reduce manual data handling and provide different functionalities according to stakeholder roles. Role-based access control will ensure that users can access only the features relevant to them.

The system can also be extended with AI-based resume screening and job-candidate matching as a future enhancement.

---

# Observation

Using multiple requirement elicitation techniques helps identify requirements from different perspectives. Interviews provide detailed stakeholder information, questionnaires collect broader user feedback, observation identifies existing workflow problems, and user personas help understand user expectations.

---

# Result

The stakeholders of the Student Placement Management System were identified, suitable requirement elicitation techniques were applied, functional and non-functional requirements were documented, user stories with acceptance criteria were prepared, and the Requirement Gathering Report was successfully completed.
